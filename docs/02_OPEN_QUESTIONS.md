# 02 — คำถามและแบบบันทึกคำตอบ

**สถานะ 2026-10-14:** Q01–Q07 ได้รับคำตอบจากเจ้าของแล้ว; Q08 และ Q09–Q28 ยังเปิดอยู่ คำแนะนำเป็นข้อเสนอ ไม่ใช่คำตอบแทนเจ้าของ

## วิธีใช้โดยไม่ถามวน

- ไม่ถามซ้ำเรื่องแนวไซไฟ ตัวเอกคนธรรมดา branching จริง VN ความสัมพันธ์ ทีม หรือการมี Level เพราะยืนยันแล้ว
- เจ้าของเลือก A/B/C หรือเขียนคำตอบเองได้ ผสมได้เมื่อไม่ขัดกัน; โมเดลอธิบาย trade-off ก่อนรวม
- Q01–Q07 บันทึกแล้ว; คำถามแกนหลักที่ต้องตอบต่อคือ Q08
- ก่อนเลือกวิธีผลิตจริง ดู Q09–Q24 เฉพาะส่วนที่กระทบ milestone ถัดไป ไม่ต้องรอคำตอบเรื่องการขายเพื่อทำ paper design
- Q25–Q28 เลื่อนได้ตาม gate ที่ระบุ คำว่า “ใช้ค่าแนะนำ” ไม่ใช่คำอนุญาตเขียน code ในรอบวางแผนนี้
- หากยังไม่ตอบ ร่างภายใต้ `S0/PROPOSED` ต่อได้ ห้ามเรียกว่าล็อกเรื่องหรือพร้อมผลิต

## A. แกนเรื่อง — ใช้ก่อนล็อก canon (G1)

### Q01 — อยากให้ปริศนาอะไรเป็นแกนเดียวที่คุมเรื่อง?

**คำตอบเจ้าของ 2026-10-14: A.** ความทรงจำถูกแก้ไข + คดีหายตัว + การปกปิดขององค์กร; ไม่มี time loop.

**แนะนำ A:** ความทรงจำถูกแก้ไข + คดีหายตัว + การปกปิดขององค์กร; ความลับตัวละครเป็นชั้นรอง ไม่มี time loop ช่วยให้ตั้งกฎและย้อนตรวจเหตุผลได้

**B:** คดีฆาตกรรมที่ความจำเป็นหลักฐานชิ้นหนึ่ง — ลดขนาด world conspiracy แต่เน้นผู้ต้องสงสัยมากขึ้น · **C:** วนซ้ำ/หลายความจริง — ต้องออกแบบกฎเวลาและข้อมูลข้ามรอบใหม่ ทำให้ S0 ใช้ตรง ๆ ไม่ได้

**ผล/ระหว่างรอ:** D01, P02–P06; ใช้ A ร่าง truth ledger แต่ห้ามยืนยันผู้กระทำผิด

### Q02 — ความสยองมาจากอะไรเป็นหลัก?

**คำตอบเจ้าของ 2026-10-14: A.** ความระแวงทางจิตวิทยา ภัยจากคนและระบบ; ไม่มีสิ่งเหนือธรรมชาติ.

**แนะนำ A:** ความไม่แน่ใจในตัวเอง คนใกล้ตัว และระบบที่ปกปิด; มีภัยจากมนุษย์ ไม่ต้องมีสัตว์ประหลาด

**B:** เอาตัวรอดจากการไล่ล่าเป็นแกน — เพิ่มกติกาภัย/ความล้มเหลว · **C:** สิ่งเหนือมนุษย์จริง — ต้องมีกฎแยก ไม่เฉลยทุกอย่างว่าเป็นภาพหลอน

**ผล/ระหว่างรอ:** D02, P02/P09; ใช้ A ทำ beat sheet และงดออกแบบภาพสยองรุนแรง

### Q03 — ผู้เล่นควรเลือกความรักแบบไหน?

**คำตอบเจ้าของ 2026-10-14: กำหนดเอง.** ไม่เลือกคู่ตั้งแต่ต้น; ช่วงกลางเรื่องเลือกว่าจะรักใครหรือไม่เลือกใครเลย การเลือกส่งผลต่อข้อมูล ฉากจบ และความสัมพันธ์ จำนวน/คุณสมบัติผู้มีเส้นทางรักยังเปิด.

**แนะนำ A:** มี romance ที่เลือกได้ 1–2 เส้นทางในเกมเต็ม โดยเส้น friendship มีข้อมูลจำเป็นครบ; slice ทดลองความไว้ใจก่อน

**B:** ความสัมพันธ์หลักคู่เดียวแต่เลือกว่าจะรักษาหรือทำลาย · **C:** รักสามเส้า/การแข่งขันเป็นแกน — เพิ่ม conflict และเงื่อนไขเฉพาะคู่

**ผล/ระหว่างรอ:** D03, P03/P04; ไม่ล็อกคู่รักหรือทำ romantic gating ของความจริงหลัก

### Q04 — คนธรรมดาที่เป็นตัวเอกเกี่ยวข้องกับอดีตของคดีแค่ไหน?

**คำตอบเจ้าของ 2026-10-14: กำหนดเอง (แทนตัวเลือก A เดิม).** ตัวเอกเคยเข้าใจ/ทดลองเรื่องนี้มาก่อน แต่เลิกสนใจแล้ว; ข่าวหรือเหตุบังเอิญและคำชวนจากใครบางคนดึงกลับมา อาจเคยทดลองสำเร็จโดยไม่บอกใครแล้วเลิกทำ และยังมีคนเชื่อว่าตัวเอกทำสำเร็จ รายละเอียดว่าอะไรสำเร็จ เหตุใดเลิก และผู้ชวนเป็นใครยังเปิดอยู่.

**แนะนำ A:** เคยทำสิ่งเล็กที่มีผลใหญ่โดยไม่รู้ข้อมูลครบ; ต้องรับผิดชอบต่อสิ่งที่ทำ แต่ไม่ใช่ผู้บงการลับ

**B:** ผู้บริสุทธิ์ถูกใช้ชื่อ/เสียง — ลดความผิดส่วนตน เพิ่มปัญหาอัตลักษณ์ · **C:** พยานที่จำไม่ได้ — เน้นสิ่งที่เห็นกับสิ่งที่เชื่อ

**ผล/ระหว่างรอ:** D03, P02/P03; อาชีพใน S0 เป็นชื่อบทบาทชั่วคราว ยังคง R03 ไม่ทำตัวเอกเป็นยอดมนุษย์

### Q05 — อยากให้หลายตอนจบต่างกันที่อะไร?

**คำตอบเจ้าของ 2026-10-14: A พร้อมข้อเพิ่ม.** มีความจริงแกนเดียว แต่ผลลัพธ์ต่างกัน; ใส่เรื่องเล็กที่ชวนคาดเดาผลต่ออนาคต โดยไม่ปล่อยปมหลักให้คลุมเครือ รายละเอียด hook ยังเปิด.

**แนะนำ A:** อดีตจริงชุดเดียว ทุก route เปิดเผยต่างมุม ชะตาคน/การเปิดเผย/ราคาที่จ่ายต่างกัน ไม่มีตอนจบเดียวที่ลบคุณค่าของทุก route

**B:** มี true ending หลังหลายรอบ — ต้องวาง meta-progression และแจ้งผู้เล่น · **C:** ความจริงบางส่วนไม่มีคำตอบตายตัว — ต้องแยกคำถามที่ตั้งใจค้างออกจาก plot hole

**ผล/ระหว่างรอ:** D04, P02/P04; S0 ใช้ A และผลท้าย slice เป็น checkpoint ไม่ใช่ ending ของเกมเต็ม

### Q06 — มีเนื้อหาอะไรไม่ต้องการ และรับความรุนแรงระดับใด?

**คำตอบเจ้าของ 2026-10-14: B.** ยอมรับการสูญเสียชัดเจน ภาพความรุนแรง และเนื้อหาทางเพศเล็กน้อย ยังไม่ระบุชนิด/ระดับ/บริบทของฉาก; ห้ามตีความเพิ่มว่าอนุญาตความรุนแรงทางเพศ.

**แนะนำ A:** โทนผู้ใหญ่เชิงอารมณ์ มีการสูญเสีย/ควบคุมความจำ/การบีบบังคับ แต่เล่าไม่โจ่งแจ้ง ไม่มีความรุนแรงทางเพศหรือการทรมานละเอียดใน baseline

**B:** เข้มขึ้นบางหมวด โดยระบุหมวดที่รับได้ · **C:** ลดความมืดและการสูญเสีย เน้นสืบสวน/ความสัมพันธ์

**ผล/ระหว่างรอ:** D02, P02/P09; ใช้ขอบเขต A แบบชั่วคราวเพื่อร่างเท่านั้น อย่าอนุมานขอบเขตส่วนบุคคลจากแนว horror; เมื่อยืนยันแล้วทำ content matrix และคำเตือนที่ไม่สปอยล์

### Q07 — ขนาดทีม/ตัวละครหลักที่อยากดูแลคือเท่าไร?

**คำตอบเจ้าของ 2026-10-14: C.** ต้องการตัวละครหลักมากกว่า 7 คน; จำนวนที่แน่นอนและกำลังผลิตยังเปิด. ถือเป็นทิศทางของเกมเต็ม ไม่ใช่คำสั่งทำทีมหลายคนพร้อมกันในทุกฉาก.

**แนะนำ A:** เกมเต็ม 7 บทบาทรวมตัวเอกและผู้หายตัว; slice มีตัวเอกกับพันธมิตรให้เลือก 2 คน เลือกร่วมทาง 1 คนต่อรอบ

**B:** ลดเหลือ 4–5 บทบาทเพื่อผูกพันลึกและผลิตง่าย · **C:** มากกว่า 7 คน/จัดทีมหลายคนพร้อมกัน — ต้องเพิ่มงบ interaction และ QA

**ผล/ระหว่างรอ:** D05, P03/P09; A เป็นเพดานร่าง ไม่ใช่คำสั่งตัดตัวละครที่เจ้าของต้องการ

### Q08 — จะใช้ขนาดเกมเป็นเป้าหมายยืดหยุ่นหรือข้อบังคับ?

**แนะนำ A:** พิสูจน์ slice 25–40 นาที แล้วเลือกระหว่างเกมสั้น 3–4 บท, กลาง 6–8 บท, หรือ 12 บทจากต้นทุนจริง

**B:** ตั้งใจ 12 บทแต่เวลาแต่ละบทยืดหยุ่น · **C:** ต้อง 12 บท × ใกล้ 1 ชั่วโมงต่อรอบ — ต้องยืนยันทรัพยากรและยอมรับ production/QA ที่เพิ่ม

**ผล/ระหว่างรอ:** D06, P01/P09/P17; ใช้ A เพื่อวางขั้นทดลอง จำนวนบททั้งสามเป็นทางเลือกวางแผน ไม่ใช่ estimate ว่าทำเสร็จเมื่อไร

## B. วิธีเล่นและเทคนิค — ตัดสินใจก่อน G2/G3 ตามงาน

### Q09 — จะให้เล่นบนอะไรเป็นเป้าหมายแรก?

**แนะนำ A:** desktop หนึ่ง OS ที่เจ้าของจะทดสอบได้จริงก่อน แล้วค่อยเพิ่ม OS · **B:** browser/มือถือผ่านเว็บก่อน · **C:** native Android หรือ iOS ก่อน

**ต้องระบุเพิ่ม:** OS/อุปกรณ์/ขนาดจอขั้นต่ำที่มีให้ทดสอบ อย่าอนุมานว่า Linux เป็นแพลตฟอร์มเกมเพราะเจ้าของใช้ Linux ในโปรเจกต์อื่น

**ผล/ระหว่างรอ:** D07, P08/P10; อ่านเอกสาร engine ได้ แต่ยังไม่เลือก exporter หรือรับรองมือถือ

### Q10 — มี engine ที่ต้องใช้หรือประสบการณ์เดิมไหม?

**แนะนำ A:** ประเมิน Ren'Py ก่อนสำหรับ VN ที่เน้นอ่าน/เลือก · **B:** Godot ถ้าระบบสำรวจ/หน้าจอซับซ้อนเป็น requirement · **C:** ยังไม่เลือก ทำ paper design ก่อน; ถ้ามี engine ที่ถนัดให้ระบุ

**ผล/ระหว่างรอ:** D07, P08/P10; ไม่มี engine lock หรือ version pin ในแผนนี้ ต้องเทียบภาษาไทย save และเป้าหมาย Q09 ก่อน

### Q11 — ภาษาเกมแรกและกลุ่มผู้อ่านคือใคร?

**แนะนำ A:** ไทยต้นฉบับก่อน เตรียม text ID สำหรับภาษาอื่น; ผู้อ่านที่ชอบ VN/mystery · **B:** ไทย+อังกฤษตั้งแต่ slice — เพิ่มงานแปลและทดสอบ layout · **C:** ภาษาอื่นเป็นต้นฉบับ โปรดระบุ

**ผล/ระหว่างรอ:** D08, P07/P08/P09; เอกสารคุยงานเป็นภาษาไทยอยู่แล้ว แต่ไม่ถือว่าเท่ากับยืนยันภาษาสินค้า

### Q12 — Level ควรโตจากอะไร?

**แนะนำ A:** milestone ความสามารถจากการทำ/เข้าใจสิ่งหนึ่ง เช่น อ่านร่องรอยการแก้ข้อมูลเป็น ไม่ต้อง grind; เปิดวิธีผ่านเหตุการณ์เพิ่ม

**B:** XP/skill tree หลายสาย — เพิ่ม balance, UI และเส้นทางล้มเหลว · **C:** ยศ/ความสามารถทีมมากกว่าตัวเอก — ต้องโยงกับ roster

**ผล/ระหว่างรอ:** D09, P06; รักษา requirement ว่ามี Level ด้วยระบบเล็กใน S0 ไม่ลบระบบเพราะยังไม่รู้สูตร

### Q13 — ผู้เล่นต้องลงมือสืบแค่ไหน?

**แนะนำ A:** สมุดหลักฐาน + เปรียบเทียบข้อขัดแย้งผ่าน choices มีคำใบ้เป็นชั้น · **B:** กระดานโยงหลักฐาน/ลากวาง · **C:** อ่านและเลือกอย่างเดียว ให้ตัวเอกสรุปหลักฐาน

**ผล/ระหว่างรอ:** D09, P05/P08; ใช้ A ใน paper design ไม่สร้าง minigame หรือ free-text input ที่ต้องพึ่ง LLM

### Q14 — ย้อนตัวเลือกและกลับมาเล่นใหม่ได้แค่ไหน?

**แนะนำ A:** save หลาย slot, load, rollback และ skip เฉพาะที่อ่านแล้ว; journal ย้อนตาม save · **B:** ย้อนเฉพาะ checkpoint · **C:** ironman/ผลถาวร — ต้องอธิบายก่อนเล่นและแยกจากโหมดปกติ

**ผล/ระหว่างรอ:** D10, P06/P08; ใช้ A ไม่มีการลงโทษผู้เล่นที่อ่านช้าหรือโหลดใหม่

### Q15 — ความกดดันด้านเวลาเป็นแบบไหน?

**แนะนำ A:** เวลาผ่านเมื่อเลือกการกระทำสำคัญ ไม่ใช่เวลาที่ใช้อ่าน · **B:** ตัวเลือกจับเวลาที่ปิดได้ · **C:** มีเวลาจริงเป็น core mechanic — ต้องแก้ accessibility และ QA

**ผล/ระหว่างรอ:** D10, P05/P08; S0 ใช้ A, ไม่มีนับวินาทีหรือ randomized deadline

### Q16 — จะแสดงความสัมพันธ์/สถานะอย่างไร?

**แนะนำ A:** แสดงท่าที/ข้อผูกมัดเป็นภาษา และแสดง Level/หลักฐานชัดเจน; ตัวเลข relation ใช้ debug เท่านั้น

**B:** แสดงเลข relation ทั้งหมด · **C:** ซ่อนเกือบทั้งหมด — ต้องทดสอบว่าผู้เล่นยังเข้าใจเหตุและผล

**ผล/ระหว่างรอ:** D10, P06/P08; ไม่มีแถบ “คนดี/คนเลว” รวมทุกความสัมพันธ์เป็นค่าเดียว

## C. การผลิต — เลือกเมื่อใกล้ใช้ทรัพยากรจริง

### Q17 — มีคนทำงานอะไรบ้าง และทำได้กี่ชั่วโมงต่อสัปดาห์?

**แนะนำวิธีตอบ:** ระบุคนเขียน/ตรวจบท/ทำภาพ/ทำเสียง/เขียนเกม/ทดสอบ พร้อมเวลาจริง; AI เป็นผู้ช่วย ไม่ใช่กำลังผลิตที่ผ่าน QA แล้ว

**ตัวเลือก:** A ทำคนเดียวกับโมเดลช่วย · B มีทีม ระบุบทบาท · C ยังไม่รู้

**ผล/ระหว่างรอ:** D11, P09; `UNKNOWN` เสมอจนมีข้อมูล ใช้สูตร capacity ใน 05 ได้แต่ห้ามใส่วันที่เสร็จแทนเจ้าของ

### Q18 — มีงบหรือวันส่งที่ผูกพันอยู่แล้วหรือไม่?

**แนะนำ A:** ตั้งเพดานเวลาและงบเฉพาะ slice ก่อน ประเมินเต็มเกมหลัง G4 · **B:** มี deadline/งบเต็มเกม ระบุตัวเลขและสิ่งที่ลดได้ · **C:** ยังไม่กำหนด

**ผล/ระหว่างรอ:** D11, P09/P17; ไม่มีการซื้อ/จ้าง/สมัครบริการ ค่าใช้จ่ายและวันส่งเป็น `UNKNOWN` ถ้าไม่ได้ให้มา

### Q19 — ภาพควรมีทิศทางและแหล่งผลิตอย่างไร?

**แนะนำ A:** VN 2D แบบภาพนิ่ง+สีหน้า เน้นชีวิตประจำวันในเมืองไซไฟ ใช้ placeholder ทดสอบก่อน แล้วเลือก style sheet หนึ่งแบบ

**B:** ภาพละเอียด/CG มากขึ้น — เพิ่มงานสร้างความต่อเนื่อง · **C:** ภาพเคลื่อนไหว/Live2D/3D — ต้องเพิ่ม production gate

**ต้องระบุเพิ่ม:** วาดเอง/จ้าง/asset pack/AI อะไรยอมรับได้; การเลือก A ไม่ได้อนุญาต AI art อัตโนมัติ

**ผล/ระหว่างรอ:** D12, P09; ยังไม่ผลิตภาพจริง ใส่ asset IDs และงานตรวจสิทธิ์ไว้ก่อน

### Q20 — เสียงและการพากย์สำคัญระดับไหน?

**แนะนำ A:** slice ใช้ข้อความครบทุกข้อมูล มี ambience/SFX แบบ placeholder ไม่มีภาระพากย์ · **B:** พากย์บางฉาก · **C:** พากย์เต็ม — ต้องวัดต้นทุนแก้บทและหลาย route

**ต้องระบุเพิ่ม:** เสียงคน/สังเคราะห์/ไม่ใช้เสียงพูด และสิทธิ์ที่มีอยู่; ไม่อนุมานอนุญาตโคลนเสียง

**ผล/ระหว่างรอ:** D12, P09; “หลักฐานเสียง” ในเรื่องใช้ transcript ได้ ไม่ต้องทำ TTS/STT

### Q21 — ตัวเอกและความสัมพันธ์ต้องให้ผู้เล่นปรับตัวตนแค่ไหน?

**แนะนำ A:** ตัวเอกเขียนบุคลิก/ประวัติหลักชัด เปลี่ยนชื่อได้ภายหลัง; ยังไม่ล็อกเพศ/รสนิยมจนเจ้าของเลือก

**B:** ตัวเอกปรับได้หลายมิติ — เพิ่มสรรพนาม บทและภาพ variant · **C:** ตัวเอกระบุชื่อ/ตัวตนทั้งหมดตามผู้เขียน

**ผล/ระหว่างรอ:** D03, P03/P07; ใช้ role IDs ไม่สร้างข้อสรุปเรื่องคู่รัก อายุ หรือความสัมพันธ์ทางเพศแทนเจ้าของ

### Q22 — การตายถาวรและความล้มเหลวควรหนักแค่ไหน?

**แนะนำ A:** fail-forward; slice เสียโอกาส/ความไว้ใจได้แต่ไม่ตายทันที เกมเต็มอาจมีการตายที่ปูเหตุชัดและไม่ใช่เดาสุ่ม

**B:** tragic outcomes มากและมี short bad endings · **C:** ไม่มีตัวละครหลักตาย เน้นความสัมพันธ์/สถานะโลก

**ผล/ระหว่างรอ:** D04, P05/P04; ร่าง ending budget ได้แต่ไม่ล็อกผู้ตายหรือเขียนฉากสูญเสียละเอียด

### Q23 — การเล่นต้องเชื่อมออนไลน์ เก็บข้อมูล หรือใช้ AI สดหรือไม่?

**แนะนำ A:** single-player offline, local save, ไม่มี analytics/accounts/LLM ระหว่างเล่น · **B:** เล่น offline แต่มี cloud save/analytics แบบเลือกใช้ · **C:** ต้องมี online/live AI — ต้องทำ architecture, privacy และค่าใช้จ่ายใหม่

**ผล/ระหว่างรอ:** D13, P08/P10; ใช้ A เป็นขอบเขตเสนอ ห้ามอ้างว่า local-only เป็นข้อห้ามผู้ใช้ที่ยืนยันแล้ว

### Q24 — มีความต้องการการเข้าถึงหรืออุปกรณ์ควบคุมเฉพาะไหม?

**แนะนำ A:** text size/speed, instant text, keyboard, contrast, ปิดเอฟเฟกต์, transcript และตรวจการอ่านหน้าจอบนเป้าหมายแรก

**B:** ต้องรองรับ screen reader/ผู้เล่นสายตาเลือนรางเป็นเกณฑ์หลักตั้งแต่ต้น · **C:** ต้อง touch/gamepad เป็นหลัก ระบุอุปกรณ์

**ผล/ระหว่างรอ:** D08, P08/P11; ใช้ A ออกแบบ UI แต่ห้ามถือว่ามี self-voicing ใน engine แล้วเกม accessible ครบ

### Q27 — ฟีเจอร์หลังเล่นจบและภาษาที่สองต้องมีในรุ่นแรกไหม?

### Q28 — จะจัดการสปอยล์ใน repository อย่างไรเมื่อ canon ยืนยันแล้ว?

**ผล/ระหว่างรอ:** D14, P02/P22; S0 ในชุดนี้ติดป้ายสปอยล์ข้อเสนอ ยังไม่เปลี่ยน visibility, ไม่ย้ายข้อมูลไปบริการอื่น และไม่อ้างว่า path `docs/` ซ่อนจากสาธารณะ
