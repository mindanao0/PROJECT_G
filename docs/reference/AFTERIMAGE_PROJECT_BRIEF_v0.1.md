# AFTERIMAGE — เมืองที่จำไม่เหมือนกัน

**Project brief / v0.1 — สำหรับตั้งต้นพัฒนา Interactive Story**

> สถานะเอกสาร: รวบรวมสิ่งที่ผู้พัฒนาเลือกไว้แล้ว แยกจากแนวคิดตัวอย่างที่ยังไม่ถือเป็น canon (เนื้อเรื่องที่ยืนยันแล้ว)

## 1. ภาพรวมโครงการ

- **ชื่อชั่วคราว:** AFTERIMAGE: เมืองที่จำไม่เหมือนกัน
- **รูปแบบ:** Interactive Story / Visual Novel
- **ฉากหลัง:** โลกอนาคต เทคโนโลยีและไซไฟ
- **แนวหลัก:** ลึกลับ, จิตวิทยา, ดราม่า, ความสัมพันธ์, สยองขวัญ, อาชญากรรม และการเติบโตของตัวละคร
- **ตัวเอก:** คนธรรมดาที่บังเอิญเข้าไปพัวพันกับเหตุการณ์ผิดปกติ
- **ขนาดเป้าหมายเบื้องต้น:** อาจประมาณ 12 บท บทละประมาณ 1 ชั่วโมง (ยังไม่สรุปและควรประเมินจากขอบเขต branch จริง)
- **วิธีเล่า:** ข้อความ บทสนทนา ตัวเลือก ภาพตัวละครและฉากแบบ Visual Novel
- **โครงสร้าง:** Branching narrative ที่การตัดสินใจเปลี่ยนเหตุการณ์สำคัญและเส้นทางที่ผู้เล่นพบได้ ไม่ใช่แค่เปลี่ยนบทสนทนาหรือข้อความเล็กน้อย

## 2. ประสบการณ์และอารมณ์ที่ต้องการ

เกมควรทำให้ผู้เล่น:

- อยากรู้ความจริงและสงสัยว่าเหตุการณ์เกิดขึ้นได้อย่างไร
- หวาดระแวงและไม่แน่ใจว่าจะเชื่อใจตัวละครใด
- ผูกพันกับตัวละครและรู้สึกเศร้าหรือสูญเสียเมื่อความสัมพันธ์แตกหัก
- รู้สึกผิดหรือเสียดายกับผลของการตัดสินใจ
- ย้อนคิดถึงคำถามว่า ถ้าเลือกอีกแบบ เหตุการณ์จะเปลี่ยนไปอย่างไร

**หลักการอารมณ์:** ตัวเลือกควรมีเหตุผลให้เลือกได้มากกว่าหนึ่งทาง และผลลัพธ์ควรทำให้ผู้เล่นเข้าใจว่าทำไมการตัดสินใจนั้นจึงเจ็บปวด ไม่ควรแปะป้ายถูก/ผิดแบบง่าย ๆ ให้ทุกการเลือก

## 3. แกนคำถามและธีม

เรื่องควรค่อย ๆ สำรวจคำถามต่อไปนี้:

1. ทำไมเหตุการณ์หลักจึงเกิดขึ้น และมีใครหรือระบบใดอยู่เบื้องหลัง?
2. ถ้าตัวเอกตัดสินใจต่างออกไป จะเกิดผลลัพธ์แบบใด?
3. ตัวละครแต่ละคนมีความสัมพันธ์ลึกซึ้งกับตัวเอกและคนอื่นอย่างไร?
4. ความจริงเบื้องหลังอดีต แรงจูงใจ และตัวตนของตัวละครแต่ละคนคืออะไร?
5. อดีตของโลกและอนาคตของโลกเชื่อมกับเหตุการณ์ปัจจุบันอย่างไร?
6. หากช่วยคนหนึ่งแล้วทำให้คนอื่นอีกหลายคนเดือดร้อน ตัวเอกควรเลือกอะไร?
7. ความรักจะนำไปสู่การเสียสละ การเลือกข้าง หรือการแข่งขันเพื่อคนคนหนึ่งได้อย่างไร?
8. อะไรทำให้ตัวละครเปลี่ยนฝ่าย ทรยศ หรือกลับมาเป็นพันธมิตร?
9. หากความทรงจำไม่น่าเชื่อถือ ความรับผิดชอบต่อตนเองและผู้อื่นควรหมายความว่าอย่างไร?

## 4. แนวคิดเรื่องตั้งต้น (ยังเป็นข้อเสนอ ไม่ใช่ canon)

ในอนาคต ผู้คนมีเทคโนโลยีที่สามารถบันทึก เรียกคืน หรือแก้ไขความทรงจำบางส่วนได้ วันหนึ่งเกิดเหตุเสียชีวิตหรือหายตัวไป และหลักฐานจากบุคคลหลายคนขัดแย้งกัน บางคนจำได้ว่าบุคคลนั้นมีตัวตน บางคนยืนยันว่าไม่เคยรู้จัก และฐานข้อมูลทางการกลับไม่มีประวัติของเขา

ตัวเอกซึ่งเป็นคนธรรมดาบังเอิญพบเศษความทรงจำที่ไม่ควรมีอยู่ ในข้อมูลนั้นมีเสียงของตัวเอกเองพูดถึงเหตุการณ์ที่ตัวเอกจำไม่ได้

**คำถามแกนที่อาจใช้เป็นเข็มทิศ:** ถ้าความทรงจำของทุกคนเชื่อถือไม่ได้ เราจะตัดสินได้อย่างไรว่าใครกำลังโกหก และเราควรรับผิดชอบต่อสิ่งที่จำไม่ได้หรือไม่?

แนวคิดนี้เป็นเพียง premise ตั้งต้น สามารถเปลี่ยนรายละเอียด ตัวเอก เหตุการณ์แรก และความจริงสุดท้ายได้ทั้งหมดหลังจากตกลงทิศทางร่วมกัน

## 5. ความสัมพันธ์และตัวละคร

ความสัมพันธ์ควรมีผลต่อทั้งข้อมูลและความอยู่รอด:

- ตัวละครแต่ละคนมีข้อมูลคนละส่วนของปริศนา จึงไม่มีใครรู้ความจริงทั้งหมด
- ผู้เล่นต้องตัดสินใจว่าจะไว้ใจใคร และใครอาจกำลังปกปิดบางอย่าง
- บางครั้งการรักษาความสัมพันธ์อาจมีราคาสูงกว่าการเปิดเผยความจริง
- ตัวละครอาจเปลี่ยนฝั่งได้ตามการตัดสินใจและแรงจูงใจ ไม่ควรเปลี่ยนฝ่ายแบบไร้เหตุผล
- การจัดทีมและความสามารถของสมาชิกอาจกำหนดวิธีผ่านสถานการณ์และเนื้อหาที่เข้าถึงได้
- เส้นความรักหรือความผูกพันควรเกิดจากการกระทำและความเข้าใจตัวละคร ไม่ใช่แค่สะสมคะแนน

## 6. แนวทางระบบที่อาจใช้

ระบบต่อไปนี้เป็นข้อเสนอสำหรับทดลอง ไม่ใช่ข้อบังคับสุดท้าย:

| ตัวแปร | หน้าที่ในเรื่อง |
|---|---|
| Trust / ความไว้ใจ | ส่งผลว่าตัวละครจะเปิดเผยข้อมูล ช่วยเหลือ หรือฝากชีวิตไว้กับตัวเอกหรือไม่ |
| Bond / ความผูกพัน | ปลดล็อกฉากส่วนตัว ความสัมพันธ์ ความรัก หรือความขัดแย้งเฉพาะตัวละคร |
| Suspicion / ความระแวง | ส่งผลให้ตัวละครสงสัยตัวเอก เปลี่ยนท่าที หรือปฏิเสธความร่วมมือ |
| Evidence / หลักฐาน | เปิดทางเลือกใหม่สำหรับสอบสวน ยืนยันหรือโต้แย้งคำให้การ |
| World State / สถานะโลก | เก็บผลกระทบวงกว้าง เช่น การเปิดเผยความจริง เสถียรภาพของเมือง หรืออิทธิพลของฝ่ายต่าง ๆ |
| Level / ความสามารถ | ใช้กับทักษะ เช่น สืบสวน เจาะระบบ โน้มน้าว และเอาตัวรอด เพื่อเปิดวิธีแก้ปัญหาใหม่ ไม่ใช่แค่เพิ่มพลัง |
| Flags / เงื่อนไขเหตุการณ์ | บันทึกการกระทำสำคัญ เช่น ช่วย/ทอดทิ้งใคร เก็บ/ทำลายหลักฐาน หรือเปิดเผย/ปิดบังความลับ |

ข้อควรระวัง: ไม่จำเป็นต้องเปิดเผยค่าทุกตัวเลขแก่ผู้เล่น และไม่ควรเพิ่มระบบถ้าไม่มีผลต่อฉาก ทางเลือก หรือผลลัพธ์อย่างชัดเจน

## 7. โครงสร้าง 12 บท (โครงสูงระดับมาก ยังไม่ล็อก)

- **บท 1–3 — ความผิดปกติ:** ตั้งต้นชีวิตประจำวัน แนะนำตัวละครและเหตุการณ์ปริศนา ให้ผู้เล่นเลือกว่าจะเชื่อใครหรือสืบทางใด
- **บท 4–6 — คนละความจริง:** เส้นทางและเหตุการณ์เริ่มแยก ผู้เล่นได้รับข้อมูลคนละชุดตามพันธมิตรและการตัดสินใจก่อนหน้า
- **บท 7–9 — ราคาที่ต้องจ่าย:** ความลับบางส่วนถูกเปิดเผย เกิดความแตกหัก การเปลี่ยนฝ่าย และผลของการตัดสินใจย้อนกลับมา
- **บท 10–12 — ความจริงและผลลัพธ์:** ผู้เล่นต้องใช้ข้อมูลที่ได้มาประกอบการตัดสินใจครั้งสุดท้าย และเผชิญผลลัพธ์ที่สอดคล้องกับประวัติการเล่น

นี่เป็นเพียงจังหวะเรื่องระดับโครงสร้าง ไม่ได้หมายความว่าทุกบทมีพล็อตเรียบร้อยแล้ว ควรวาง story graph และประมาณปริมาณเนื้อหาก่อนยืนยันความยาวบทละ 1 ชั่วโมง

## 8. หลักการออกแบบ Branching Narrative

1. ให้ทางเลือกสำคัญเปลี่ยนอย่างน้อยหนึ่งอย่างที่มีความหมาย: เหตุการณ์, พันธมิตร, ข้อมูลที่เข้าถึงได้, ผู้ที่รอด, สถานะโลก หรือทางเลือกในอนาคต
2. เก็บผลของการกระทำเป็น flags ที่ตรวจสอบได้ เพื่อให้ผลลัพธ์ภายหลังไม่ดูสุ่มหรือไร้เหตุผล
3. สามารถให้บางเส้นทางแยกเป็นเหตุการณ์เฉพาะ แล้วกลับมาบรรจบที่วิกฤตหลักในสภาพต่างกัน เพื่อควบคุมขอบเขตการผลิต
4. แต่ละเส้นทางควรเปิดเผยความจริงคนละด้าน แต่ไม่ควรใช้การหักมุมที่ลบล้างข้อมูลก่อนหน้าโดยไม่มีเบาะแสรองรับ
5. การตาย การทรยศ หรือการเสียโอกาสสำคัญควรมีการปูเหตุและผล ไม่ควรเกิดเพียงเพราะผู้เล่นเดาตัวเลือกที่ผู้เขียนต้องการไม่ถูก
6. ควรออกแบบฉากทางเลือกให้มีเหตุผลเชิงตัวละคร ไม่ใช่แค่ค่าความสัมพันธ์สูง/ต่ำ

## 9. สิ่งที่ยังไม่ตัดสินใจ

- กลไกหลักของปริศนา: ความทรงจำ / ฆาตกรรม / สมคบคิด / เหตุการณ์วนซ้ำ / ตัวตนของตัวละคร
- ลักษณะความสยองขวัญ: จิตวิทยา, ภัยเหนือมนุษย์, การเอาตัวรอด หรือผสมกัน
- ระดับและรูปแบบความรัก: รักสามเส้า, เส้นความรักหลายคน, ความรักที่เกี่ยวข้องกับการทรยศ หรือเน้นมิตรภาพ
- ตัวเอกมีส่วนกับคดีในระดับใด และเริ่มต้นด้วยความรู้อะไร
- ความจริงสุดท้ายและรูปแบบของ ending
- จำนวนตัวละครหลัก จำนวนเส้นทาง และขอบเขตการแตกแขนงที่ทีมผลิตได้จริง
- เทคโนโลยีความทรงจำมีกฎและข้อจำกัดอย่างไร
- รูปแบบศิลป์ เพลง เสียง และแพลตฟอร์มเป้าหมาย

## 10. ขั้นตอนถัดไปที่แนะนำ

1. เลือกกลไกปริศนาหลักและกฎของเทคโนโลยีความทรงจำ
2. เขียน premise ฉบับยืนยันในหนึ่งย่อหน้า พร้อมคำถามกลางของเรื่อง
3. สร้างตัวละครหลัก 5–7 คน โดยกำหนดเป้าหมาย ความลับ ข้อมูลที่รู้ ความสัมพันธ์กับตัวเอก และเงื่อนไขเปลี่ยนฝ่าย
4. วาง story graph ของบท 1–3 เพื่อทดสอบการแตกแขนงด้วย vertical slice ก่อนเขียนครบ 12 บท
5. กำหนดตัวแปรและเงื่อนไขอย่างชัดเจน แล้วทดสอบว่าตัวเลือกส่งผลให้ประสบการณ์ต่างกันจริงหรือไม่
6. ประเมินขนาดงานจากจำนวนฉาก บทสนทนา ภาพ และเส้นทางที่ไม่สามารถใช้ซ้ำได้ ก่อนยืนยันเวลาการเล่น

## 11. แบบคำถามสำหรับรอบออกแบบถัดไป

## 12. บันทึกส่งต่อสำหรับเริ่มแชตใหม่ (สำคัญ)

ส่วนนี้ทำขึ้นเพื่อให้เปิดแชตใหม่แล้วทำงานต่อได้โดยไม่ต้องเล่าเรื่องทั้งหมดซ้ำ ใช้ข้อมูลด้านบนและส่วนนี้เป็นบริบทตั้งต้น

### 12.1 สถานะที่ยืนยันแล้วจากผู้พัฒนา

ผู้พัฒนาเลือกแนวคิดตั้งต้น **A — AFTERIMAGE: เมืองที่จำไม่เหมือนกัน** ให้เป็นแนวคิดหลักที่ต้องการพัฒนาต่อ โดยยอมรับชื่อและทิศทางนี้เป็นจุดเริ่มต้น ไม่ได้หมายความว่ารายละเอียดพล็อตตัวอย่างทุกอย่างถูกล็อกแล้ว

คำตอบจากแบบสำรวจรอบแรกของผู้พัฒนา:

- **อารมณ์หลังเล่นจบ:** รู้สึกผิดกับการตัดสินใจ, เสียดายกับสิ่งที่เลือก, เศร้าและรู้สึกสูญเสีย, หวาดระแวงและไม่ไว้ใจใคร, อยากรู้ความจริง
- **บทบาทตัวเอก:** คนธรรมดาที่บังเอิญเข้าไปพัวพันกับเหตุการณ์บางอย่าง
- **ฉากหลัง:** โลกอนาคต / เทคโนโลยี / ไซไฟ
- **แนวเรื่อง:** ลึกลับ / จิตวิทยา, ดราม่า / ความสัมพันธ์, สยองขวัญ, อาชญากรรม, ชีวิตประจำวัน / การเติบโต
- **คำถามและธีมที่สนใจ:** ทำไมเหตุการณ์จึงเกิดขึ้น; ถ้าเลือกต่างออกไปจะเกิดอะไร; ความสัมพันธ์ลึกซึ้งของตัวละครกับตัวเอก; ความจริงเบื้องหลังตัวละครแต่ละคน; อดีตและอนาคตของโลก; ศีลธรรมของการช่วยคนหนึ่งแล้วทำให้คนอื่นเดือดร้อน; ความรักที่ต้องเลือกหรือแย่งชิง; การเปลี่ยนฝ่าย; การทรยศ
- **ระดับการแตกแขนง:** อยากให้ทางเลือกแตกแขนงจริงจนผู้เล่นอาจพบเหตุการณ์สำคัญคนละชุด
- **ความสัมพันธ์:** ผู้เล่นต้องตัดสินใจว่าจะเชื่อใจใครและใครอาจหักหลัง; ตัวละครแต่ละคนมีข้อมูลคนละส่วนของปริศนา; บางครั้งการรักษาความสัมพันธ์อาจสำคัญกว่าการเปิดเผยความจริง; ตัวละครเป็นส่วนหนึ่งของการจัดทีมและเอาตัวรอด
- **ขนาดเป้าหมาย:** ยังไม่รู้แน่ชัด แต่อาจประมาณ 12 บท บทละประมาณ 1 ชั่วโมง ทั้งหมดนี้เป็นประมาณการเบื้องต้น ต้องทบทวนตามขอบเขตงานจริง
- **รูปแบบการเล่น:** อ่านข้อความ บทสนทนา และเลือกคำตอบ; มีระบบค่าความสัมพันธ์ สถานะ และ Level; นำเสนอแบบ Visual Novel พร้อมภาพตัวละครและฉาก

### 12.2 คอนเซปต์ A ที่เสนอและได้รับเลือกให้พัฒนาต่อ

**AFTERIMAGE: เมืองที่จำไม่เหมือนกัน** — โลกอนาคตที่เทคโนโลยีสามารถบันทึก เรียกคืน หรือแก้ไขความทรงจำได้บางส่วน เกิดคดีหรือการหายตัวไปซึ่งคำให้การและความทรงจำของแต่ละคนขัดแย้งกัน บางคนจำบุคคลหนึ่งได้ บางคนปฏิเสธว่าเคยพบเขา ขณะที่ฐานข้อมูลทางการไม่พบหลักฐานว่าเขาเคยมีตัวตน ตัวเอกพบเศษความทรงจำที่ไม่ควรมีอยู่ และมีเสียงของตัวเอกพูดถึงเหตุการณ์ที่ตัวเองจำไม่ได้

คำถามกลางเบื้องต้น: **หากความทรงจำไม่น่าเชื่อถือ เราจะรู้ได้อย่างไรว่าใครโกหก และเราต้องรับผิดชอบต่อสิ่งที่ตัวเองจำไม่ได้หรือไม่?**

สิ่งเหล่านี้ยังเป็น premise สำหรับพัฒนา ไม่ได้กำหนดผู้ร้าย ความจริงสุดท้าย กฎเทคโนโลยี หรือฉากเปิดเกมอย่างเป็นทางการ ผู้ช่วยในแชตใหม่ควรร่วมออกแบบก่อนล็อก canon

### 12.3 คำถามสำคัญที่ผู้พัฒนายังไม่ได้ตอบ

ผู้ช่วยก่อนหน้าได้เสนอคำถามรอบที่สองไว้ 5 หมวด ผู้พัฒนายังไม่ได้ส่งคำตอบของหมวดเหล่านี้ ณ เวลาสร้างเอกสารฉบับนี้:

1. **ปริศนาหลัก:** (ก) ความทรงจำและความจริงถูกบิดเบือน (ข) คดีฆาตกรรมที่ทุกคนมีแรงจูงใจ (ค) สมคบคิดและความลับของโลกอนาคต (ง) เหตุการณ์วนซ้ำและอนาคตเปลี่ยนตามการเลือก (จ) ตัวตน/ความลับของทุกตัวละคร หรือเสนอทางเลือกใหม่
2. **ความสยองขวัญ:** (ก) หลอนทางจิตใจและระแวงผู้คน (ข) ภัยเหนือมนุษย์/ปรากฏการณ์ผิดปกติ (ค) เอาตัวรอดจากมนุษย์และระบบ (ง) ผสมหลายรูปแบบ หรือเสนอทางเลือกใหม่
3. **ความรักและความสัมพันธ์:** (ก) ต้องเลือกระหว่างคนรักกับสิ่งที่เชื่อว่าถูกต้อง (ข) รักสามเส้าหรือแข่งขันเพื่อคนคนเดียว (ค) ความรักและการทรยศเชื่อมกับปริศนา (ง) ผู้เล่นเลือกเส้นความสัมพันธ์ได้หลายทาง (จ) เน้นมิตรภาพมากกว่าโรแมนติก หรือเสนอทางเลือกใหม่
4. **จุดเริ่มต้นของตัวเอก:** (ก) คนธรรมดาพบว่าตัวเองมีส่วนกับคดี (ข) ผู้บริสุทธิ์ถูกใส่ร้าย (ค) พยานที่จำเหตุการณ์สำคัญไม่ได้ (ง) คนที่คนรอบตัวรู้เรื่องอดีตมากกว่าตัวเอง หรือเสนอทางเลือกใหม่
5. **รูปแบบตอนจบ:** (ก) หลายตอนจบที่ต่างกันอย่างมีนัยสำคัญ (ข) ความจริงหลักเหมือนเดิมแต่ชะตากรรมต่างกัน (ค) แต่ละเส้นทางเปิดเผยความจริงคนละด้าน (ง) ตอนจบกำกวม (จ) ผสมหลายรูปแบบ หรือเสนอทางเลือกใหม่

ไม่จำเป็นต้องบังคับให้ผู้พัฒนาเลือกจากรายการเท่านั้น สามารถรวมหลายตัวเลือก ปรับแก้ หรือพิมพ์แนวคิดเองได้

### 12.4 ขั้นตอนการทำงานหลังจากคำตอบชุดที่สอง

ดำเนินการตามลำดับนี้ และส่งผลลัพธ์ที่จับต้องได้ในแต่ละขั้น:

1. รวมคำตอบเป็น **Core Premise** 1 ย่อหน้า, logline 1 ประโยค, ธีมหลัก, คำถามกลาง และคำมั่นทางอารมณ์ที่เกมจะมอบให้ผู้เล่น
2. ออกแบบกฎเทคโนโลยีความทรงจำ: ทำอะไรได้, ทำอะไรไม่ได้, ใครเข้าถึงได้, มีร่องรอยอะไร, ความผิดพลาดเกิดอย่างไร และกฎใดที่ผู้เล่นใช้อนุมานความจริงได้ ต้องหลีกเลี่ยงเทคโนโลยีที่แก้ปัญหาได้ทุกอย่าง
3. สร้างตัวละครหลักประมาณ 5–7 คนเป็นฉบับร่าง: เป้าหมายภายนอก, ความต้องการภายใน, ความกลัว, ความลับ, สิ่งที่รู้จริง, สิ่งที่เชื่อผิด, ความสัมพันธ์กับตัวเอกและคนอื่น, เหตุผลที่โกหก, เงื่อนไขที่ทำให้ช่วย/ทรยศ/เปลี่ยนฝั่ง และเส้นทางที่อาจจบลง
4. สร้าง **relationship map** และ **knowledge map** เพื่อให้รู้ว่าใครรู้ข้อมูลใด ใครไว้ใจหรือขัดแย้งกับใคร และผู้เล่นจะค้นพบข้อมูลผ่านทางไหน
5. วางเหตุการณ์หลัก 12 บทในระดับ beat sheet โดยแต่ละบทต้องมีเป้าหมาย ความขัดแย้ง การค้นพบ จุดตัดสินใจ ผลระยะสั้น และผลที่อาจเกิดภายหลัง
6. ลงรายละเอียดบท 1–3 เป็น **vertical slice**: scene list, choice nodes, flags, conditional branches, จุดรวมเส้นเรื่อง และตัวอย่างบทสนทนาของฉากสำคัญ อย่าเขียนครบ 12 บทแบบละเอียดก่อนทดลองว่าระบบทำงานได้หรือไม่
7. สร้างผัง **branch graph** ที่แสดงทางเลือกจริงและจุดที่เส้นเรื่องแตกแขนง/กลับมาบรรจบ พร้อมป้องกันเส้นทางที่ทำให้เนื้อหาบวมเกินขอบเขต
8. ทำ state/flag specification ระบุชื่อตัวแปร ชนิด ค่าเริ่มต้น จุดที่เปลี่ยน และผลที่ตรวจสอบได้ เช่น Trust, Bond, Suspicion, Evidence, World State, Level และ flags เฉพาะเหตุการณ์ โดยอย่าใช้ระบบใดถ้าไม่ส่งผลต่อเกม
9. วางแผนตอนจบและเงื่อนไขการปลดล็อกอย่างยุติธรรม ให้เบาะแสที่จำเป็นเข้าถึงได้หรือมีวิธีชดเชย และให้เหตุผลของผลลัพธ์ย้อนตรวจสอบได้
10. เมื่อโครงสร้างหลักแน่นขึ้น จึงทำเอกสารผลิตงาน: character bible, scene outline, narrative design document, asset list, implementation plan, testing checklist และ scope estimate

### 12.5 หลักการร่วมมือที่แชตใหม่ควรยึด

- คุยกับผู้พัฒนาเป็นภาษาไทย เว้นแต่ขอให้ใช้ภาษาอื่น
- ใช้เอกสารนี้เป็นบริบทหลัก แต่ให้คำตอบใหม่ของผู้พัฒนามีลำดับความสำคัญสูงกว่าแนวคิดตัวอย่างในเอกสาร
- อย่าถามซ้ำในสิ่งที่ผู้พัฒนาตอบไว้แล้วในหัวข้อ 12.1
- แยกทุกครั้งระหว่าง **ยืนยันแล้ว**, **ข้อเสนอ**, และ **ยังไม่ตัดสินใจ** เพื่อป้องกันการยึดพล็อตร่างเป็นข้อเท็จจริงถาวร
- ช่วยจัดระบบความคิดและให้ตัวเลือกที่มีความหมาย แต่อย่าสร้างรายละเอียดสำคัญมากมายแทนผู้พัฒนาโดยไม่ทำเครื่องหมายว่าเป็นข้อเสนอ
- อย่าเริ่มด้วยการเขียนบทเต็มทันที ให้ยืนยันแกนปริศนาและตัวละครก่อน แล้วจึงออกแบบ branch graph
- ทุก choice สำคัญต้องมีเหตุผล มีผลที่ติดตามได้ และอาจสร้างผลระยะยาว; หลีกเลี่ยงตัวเลือกที่เป็นเพียงภาพลวงตา เว้นแต่เกมตั้งใจให้ผู้เล่นค้นพบเรื่องนี้
- ให้ระวัง scope ของเกม 12 บท × 1 ชั่วโมง เป็นโครงการขนาดใหญ่สำหรับ branching narrative จึงควรพิสูจน์แนวคิดด้วย vertical slice ก่อนรับรองขอบเขตนี้
- เวลาเสนอเนื้อเรื่อง ให้บอกชัดว่าส่วนไหนเป็น canon ที่ผู้พัฒนายืนยัน และส่วนไหนเป็นข้อเสนอใหม่
- อย่าอ้างว่าได้อ่านหรือเขียน repository บน GitHub แล้ว หากยังไม่ได้ใช้เครื่องมือที่ยืนยันความสำเร็จได้จริง

### 12.6 Repository และสถานะการซิงก์

- Repository ที่ผู้พัฒนาระบุ: https://github.com/mindanao0/PROJECT_G.git
- ตำแหน่งไฟล์ที่แนะนำ: `docs/AFTERIMAGE_PROJECT_BRIEF.md`
- **สถานะซิงก์:** ยังไม่ได้ยืนยันว่าไฟล์นี้ถูก commit/push เข้า GitHub; ไฟล์นี้ถูกสร้างไว้ให้ดาวน์โหลดในแชตเท่านั้น ณ ตอนบันทึก
- หากมี GitHub connector/เครื่องมือ repository ที่เชื่อมต่อและได้รับอนุญาตในแชตใหม่ ให้ตรวจสอบโครงสร้างและไฟล์เดิมก่อน ห้ามเขียนทับไฟล์สำคัญหรือ commit โดยไม่ตรวจ diff
- หากไม่มีเครื่องมือเขียน GitHub ให้บอกตรง ๆ และให้ผู้พัฒนาดาวน์โหลด/อัปโหลดไฟล์ด้วยตนเอง แทนการอ้างว่าทำสำเร็จ

### 12.7 ข้อความเริ่มงานสำหรับคัดลอกไปใช้ในแชตใหม่

คัดลอกข้อความด้านล่างนี้ไปพร้อมกับการแนบไฟล์นี้ในแชตใหม่:

> เรากำลังพัฒนาเกม Interactive Story / Visual Novel ชื่อชั่วคราว **AFTERIMAGE: เมืองที่จำไม่เหมือนกัน** โปรดอ่านไฟล์ `AFTERIMAGE_PROJECT_BRIEF.md` ทั้งหมดก่อนตอบ และใช้เป็นบริบทหลักของโปรเจกต์
>
> สิ่งที่ฉันยืนยันแล้วอยู่ในหัวข้อ 12.1 ส่วน premise เรื่องความทรงจำและโครงสร้าง 12 บทยังเป็นข้อเสนอที่แก้ไขได้ ฉันยังไม่ได้ตอบคำถามรอบสองในหัวข้อ 12.3
>
> โปรดอย่าถามคำถามที่ฉันตอบแล้วซ้ำ ให้ดำเนินต่อจากคำถาม 5 หมวดในหัวข้อ 12.3 โดยนำเสนอคำถามอย่างเป็นระเบียบ ตอบทีละข้อหรือให้ตอบพร้อมกันก็ได้ เมื่อฉันตอบแล้ว ให้ทำตามลำดับงานในหัวข้อ 12.4: เริ่มจาก Core Premise และกฎเทคโนโลยีความทรงจำ จากนั้นตัวละคร relationship/knowledge map โครง 12 บท branch graph และรายละเอียด vertical slice ของบท 1–3
>
> ช่วยฉันในฐานะ narrative designer โดยใช้ภาษาไทย แยกสิ่งที่ยืนยันแล้วออกจากข้อเสนอเสมอ เน้นความต่อเนื่องของปริศนา ความสมเหตุสมผลของแรงจูงใจ การเลือกที่เปลี่ยนเหตุการณ์จริง และผลสะเทือนทางอารมณ์ อย่าเขียนบทเต็มทั้งหมดก่อนที่แกนเรื่องและโครงสร้างจะตกลงกัน
>
> Repository ที่เกี่ยวข้องคือ https://github.com/mindanao0/PROJECT_G.git แต่ห้ามอ้างว่าได้อ่านหรือเขียน repo แล้ว เว้นแต่เครื่องมือที่ใช้จะยืนยันการเข้าถึงหรือการเปลี่ยนแปลงนั้นจริง
